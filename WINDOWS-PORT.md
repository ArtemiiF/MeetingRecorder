# Windows-порт: план

Срез: `b0e0b97` (v1.4.14), 2026-08-19. Якоря `file:line` протухают — при расхождении верить коду.

Сейчас приложение **macOS / Apple Silicon only**: единственный build-таргет — `mac` dmg+zip `arm64`
(`package.json` → `build.mac`), Python-рантайм качается по захардкоженному `aarch64-apple-darwin`
(`main.js:1284`), системный звук берётся Core Audio tap'ом (`audiotee`), транскрипция по умолчанию
идёт через MLX (Metal). Порт — не флаг сборки, а замена трёх нативных кусков плюс расщепление
зависимостей по платформе.

---

## Решения до кода

Каждое меняет объём работы; без ответов фазы 2-5 не начинать.

**D1. Кто захватывает системный звук на Windows.**
- (a) **Питон, `PyAudioWPatch`** (форк PyAudio с WASAPI loopback; `pyaudiowpatch-0.2.12.8-cp311-win_amd64.whl` на PyPI — проверено). Новая подкоманда `backend.py record-system`, JS просто спавнит второй backend-процесс вместо `AudioTee`. Контракт IPC (`record-event` / `level` / `system-audio-error`) сохраняется — весь renderer не трогается. Минус: `WavWriter` и замер уровня для системной дорожки дублируются на питоне.
- (b) `sounddevice` + PortAudio WASAPI loopback — та же идея, другая библиотека; PortAudio уже приезжает с PyAudio.
- (c) Node-native (`naudiodon` и подобные) — держит запись в main.js как сейчас, но библиотеки слабо поддерживаются и это ещё один нативный бинарь в asarUnpack.

Рекомендация — **(a)**: платформенное различие целиком уезжает в питон, JS-слой становится однородным.

**D2. Движок транскрипции на Windows.**
`mlx` 0.31.1 колёс под win нет (проверено на PyPI: только macosx_arm64 + manylinux), `mlx-metal` — mac-only по определению. Варианты:
- (a) `--engine whisper` (openai-whisper) — **ветка уже есть в коде**, `backend.py:531-544`, ноль новой логики транскрипции. Медленно на CPU.
- (b) `faster-whisper` (CTranslate2) — новая ветка движка, кратно быстрее на CPU и на CUDA, но тянет cuDNN-зависимости для GPU-режима.

Рекомендация — (a) для первого рабочего билда, (b) отдельным шагом после.

**D3. GPU.** `pipe.to(torch.device("mps"))` в диаризации (`backend.py:732-734`) — единственная привязка к Metal. На Windows: CPU-only (просто и предсказуемо) или `torch.cuda.is_available()` + CUDA-колёса торча с `--index-url download.pytorch.org/whl/cuXXX` (быстрее, но установщик получает второй источник пакетов и ветку под наличие NVIDIA).

**D4. Апдейтер.** Текущий скачивает zip, распаковывает `ditto`, снимает карантин `xattr`, подменяет `.app` и перезапускается (`main.js:1656-1830`). На Windows живой `.exe` нельзя переписать под собой. Варианты: скачивать NSIS-инсталлятор из релиза и запускать `/S` detached перед `app.quit()`; либо `electron-updater` со Squirrel. Рекомендация — первое: меньше нового и переиспользует уже существующий код скачивания релизного ассета.

**D5. Целевая архитектура — только `x64`.** Windows-on-ARM отпадает: под `win_arm64` нет колеса торча (проверено: у `torch` 2.11.0 из win-колёс только `cp311-win_amd64`).

## Что НЕ ломается

Сводка LLM ходит в LM Studio на `http://localhost:1234/v1/chat/completions` — кросс-платформенно.
SQLite-индекс, presets/manifest-слой, весь renderer, Obsidian-выход (`main.js:104` — `path.join(os.homedir(), "Documents", ...)`, разделители уже через `path`) переносятся без правок.
`fs.statfsSync` (disk-guard) на Windows работает.

## Фаза 1. Платформенный слой (мак не меняется)

Цель: все ветки `darwin`/`win32` собрать в чистых функциях `lib/mainutil.js`, покрыть юнит-тестами, поведение на маке — байт в байт прежнее.

| Что | Якорь | Действие |
|---|---|---|
| путь до интерпретатора | `main.js:89` `BACKEND_ENV/python/bin/python3.11` | на win layout другой: `python/python.exe`, `bin/` нет. Ввести `pythonRelPath(platform)` |
| фоллбэк «голого» питона | `lib/mainutil.js:581` `return "python3"` | на win — `python` |
| ffmpeg | `main.js:90` `BACKEND_ENV/bin/ffmpeg` | `ffmpeg.exe` |
| бинарь audiotee | `lib/mainutil.js:610` | на win не существует — резолвер должен возвращать `null`, вызывающий код ветвиться |
| ассеты трея | `lib/mainutil.js:625` `trayTemplate*.png` | template-картинка — маковое понятие (авто-инверсия). Нужна цветная `tray.ico`/png |

## Фаза 2. Бутстрап бэкенда на Windows

Установщик (`main.js:1400-1476`) качает три вещи и всё три — маковые.

1. **Python.** Тот же тег релиза `python-build-standalone`, другой ассет:
   `cpython-3.11.15+20260623-x86_64-pc-windows-msvc-install_only.tar.gz` — существование проверено через GitHub API. Свой `sha256` (снять и запинить).
2. **Распаковка.** `runInstallStep("tar", ...)` — на Windows 10+ `tar.exe` (bsdtar) есть в системе и умеет и `.tar.gz`, и `.zip`. То есть шаг ffmpeg'а (`unzip -o`, `main.js:1429`) на win заменяется тем же `tar -xf` — без новых npm-зависимостей. Проверить на целевой машине до того, как закладываться.
3. **ffmpeg.** `osxexperts.net` (`main.js:1289`) → сборка BtbN (`FFmpeg-Builds`, ассет `win64-gpl`). **Пинить конкретный тег релиза, не `-latest-`**: `latest`-ассеты перезаливаются и запиненный sha256 отвалится молча.
4. `fs.chmodSync(..., 0o755)` (`main.js:1434`) на Windows бессмысленен, но безвреден — можно оставить.

Атомарная подмена каталога через `renameSync` (`main.js:1455-1460`) на NTFS работает, но упадёт, если какой-нибудь процесс держит файл открытым — сюда нужен ретрай, на маке этой проблемы нет.

## Фаза 3. Захват звука

- **Микрофон** уже кросс-платформенный: PyAudio (`backend.py:124-183`), колесо `PyAudio-0.2.14-cp311-cp311-win_amd64.whl` на PyPI есть (проверено). `vendor/wheels/` содержит только маковое колесо — на win либо тянуть с PyPI, либо доложить туда win-колесо.
- **Системный звук** — по D1. Точка отреза в JS: `main.js:806-845` (создание `AudioTee`, `sysWav`, обработчики `data`/`error`). При варианте (a) весь этот блок на win заменяется вторым `runBackend(["record-system", ...])`, а `stop-recording` (`main.js:855-865`) — той же процедурой «`stop\n` в stdin + ожидание события», что уже используется для микрофона.
- Остановка процессов: `recordProc.kill("SIGTERM")` (`main.js:869`) на Windows сигналов не имеет — это жёсткий kill. Штатный путь (`stdin "stop\n"`) уже правильный; проверить, что аварийная ветка не оставляет недописанный WAV.
- Микширование `mix` через ffmpeg (`main.js:884-895`) платформенно нейтрально.

## Фаза 4. ML-зависимости и модели

- `requirements.txt` — расщепить маркерами окружения: `mlx`, `mlx-metal`, `mlx-whisper` → `; sys_platform == "darwin"`; win-движок (D2) → `; sys_platform == "win32"`. `torch` 2.11.0 win-колесо есть.
- `backend.py:732-734` — `torch.backends.mps` → выбор устройства по платформе (D3).
- `backend.py:2857` `--engine` по умолчанию `mlx`; на win дефолт должен приходить другой (либо из main.js при спавне — `main.js:1076`, либо автоопределением в питоне).
- **Setup-gate завязан на MLX-модель.** `lib/mainutil.js:694` `whisperModelDir` указывает на кэш `mlx-community/whisper-large-v3-turbo`; стена первого запуска считает приложение неготовым, пока этой папки нет. На Windows модель другая — гейт и `download-models` в `backend.py` должны сверяться с моделью выбранного движка, иначе win-сборка навсегда упрётся в setup-стену.
- Диаризация pyannote и silero-VAD — чистый torch, портируются как есть.

## Порядок и критерии приёмки

1. Ф1 — мак зелёный, тесты на резолверы путей есть. *Ничего не сломано.*
2. Ф2 — на Windows кнопка «Установить бэкенд» доводит до конца: питон + ffmpeg + pip, маркер записан.
3. Ф3 — запись даёт непустые `mic.wav` и `system.wav`, `mixed.wav` содержит обе стороны разговора.
4. Ф4 — `process` доходит до транскрипта и сводки на win-движке.
5. Ф5+Ф7 — `dist:win` собирается, boot-smoke на распакованной сборке зелёный.
6. Ф6 — первый запуск на чистой машине проходит setup-стену без ручных действий.

## Риски

- **Setup-гейт под MLX-модель** (Ф4) — если пропустить, win-сборка не пускает дальше первого экрана при полностью рабочем бэкенде.
- **Дрейф ассетов ffmpeg** — `-latest-` ассеты BtbN перезаливаются; пин обязателен.
- **Скорость без GPU** — openai-whisper на CPU может сделать обработку часовой встречи неприемлемо долгой; это аргумент за faster-whisper (D2b) раньше, а не позже.
- **Тестировать порт можно только на реальной Windows-машине** — WASAPI loopback, NTFS-локи при подмене каталогов и апдейтер под CI не проверяются.
